CN-GPU mining secures Conceal's proof-of-work network. Core defines the algorithm and network rules. Mining costs depend on your hardware, electricity, software, pool, network connection, and the CCX market. This guide does not estimate profit or recommend a miner or pool.

## How CN-GPU mining works

A miner requests work from a node and tries proof-of-work nonces. When the work meets the network rules, it produces a candidate block. The node validates and submits that block. The network assigns a reward only after accepting a valid block. See the [Core miner implementation](https://github.com/ConcealNetwork/conceal-core/blob/master/src/CryptoNoteCore/Miner.cpp) and [consensus configuration](https://github.com/ConcealNetwork/conceal-core/blob/master/src/CryptoNoteConfig.h) for the code that applies these rules.

In solo mining, your miner submits work through your node. A pool coordinates work from many miners and uses its own accounting rules. A pool share is not an accepted network block. Check the pool's current fees, payout rules, and availability before connecting.

## Before connecting hardware

1. Read the current [Core consensus configuration](https://github.com/ConcealNetwork/conceal-core/blob/master/src/CryptoNoteConfig.h) and [Core releases](https://github.com/ConcealNetwork/conceal-core/releases) before choosing software or updating a host.
2. Obtain mining software only from a source you independently trust, then verify its publisher, release notes, and any available checksum or signature. This documentation does not endorse third-party miners.
3. Use a wallet address that you control and verify it carefully before starting work. Keep recovery material out of mining hosts, scripts, tickets, and chat.
4. Check the [live Conceal explorer](https://explorer.conceal.network/) for current network and pool-directory information immediately before acting. The directory is live data, not a fixed list in this guide.

## Operational boundaries

Confirm the software, wallet address, and network settings on your own host. Keep the host patched and restrict administrative access. Check local logs for unexpected processes or configuration changes.

Pool availability and terms can change without notice. Assess a pool independently at the time you use it; this guide intentionally does not publish a pool comparison or standing performance figures.
