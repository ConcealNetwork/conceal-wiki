Build against the interface shipped with your installed Core version. Check the Core RPC specification before relying on methods, response fields, or security behaviour.

## Daemon RPC reference

Start with the Core [JSON RPC OpenAPI document](https://github.com/ConcealNetwork/conceal-core/blob/master/docs/rpc/openapi/json_methods.yaml) and [RPC documentation](https://github.com/ConcealNetwork/conceal-core/tree/master/docs/rpc). Read the files for the Core release you deploy before adding an endpoint to an automated workflow.

Keep RPC private by default. It can disclose service state or trigger expensive operations. Use a test environment for integration work and give service accounts only the permissions they need. Keep credentials and wallet recovery material out of source control, browser consoles, issues, and logs.

## JavaScript and TypeScript entry points

Conceal maintains these JavaScript and TypeScript projects:

- [Conceal API](https://github.com/ConcealNetwork/conceal-api), a JavaScript/Node.js RPC interface.
- [conceal-lib-js](https://github.com/ConcealNetwork/conceal-lib-js), JavaScript and WebAssembly cryptographic primitives.
- [conceal-wallet-sdk](https://github.com/ConcealNetwork/conceal-wallet-sdk), a typed wallet SDK built on the library primitives.

Check each repository's package metadata, releases, compatibility notes, and source before adding it to an application. Test the version you install against the Core version you run.

## Integration checks

Pin and review dependencies. Test successful and rejected responses, and record the Core version and network in the test plan. Compare network data with the [Conceal block explorer](https://explorer.conceal.network/) when appropriate.
